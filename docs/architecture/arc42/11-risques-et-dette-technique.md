# 11. Risques et dette technique

> Les risques connus et la dette technique, par ordre de priorité.

| Risque / dette | Probabilité | Impact | Mesure envisagée |
|---|---|---|---|
| Outil PowerShell ou terminal personnel en mode `local` : `openspec` et `archgate` introuvables (`node_modules/.bin` absent du `PATH`) | Moyenne | Faible | `npm run claude` ou `npx` ; le hook de session couvre l'outil Bash, le hook qualité, la CI et l'audit ajoutent déjà `node_modules/.bin` au `PATH` ([ARCH-007](../adrs/ARCH-007-installation-des-cli-d-outillage.md)) |
| Mise à jour manuelle des `devDependencies` en mode `local` (Dependabot ne couvre que `github-actions`) | Moyenne | Faible | `npm install --save-exact` ([ARCH-007](../adrs/ARCH-007-installation-des-cli-d-outillage.md)) |
| `package.json` existant conservé tel quel : `devDependencies` à ajouter à la main | Moyenne | Faible | Documenté dans l'ADR |
| Deux versions de chaque modèle à maintenir (français et langue traduite) | Haute | Moyen | Modifier les deux dans la même PR ; tests de parité ([ARCH-008](../adrs/ARCH-008-modeles-de-documentation-par-langue.md)) |
| Écart de sens entre deux versions, ou français sans accent dans un modèle sans version traduite : non détectable par les tests | Moyenne | Moyen | Relecture en PR ([ARCH-008](../adrs/ARCH-008-modeles-de-documentation-par-langue.md)) |
| Langue autre que `fr` et celles des `templates.*` du module `core` refusée (le skill ne traduit plus) | Moyenne | Faible | Ajouter un dossier `templates.<code>/` ([ARCH-008](../adrs/ARCH-008-modeles-de-documentation-par-langue.md)) |
| Étape non vérifiable marquée faite à tort : crue par la reprise | Moyenne | Moyen | L'audit de la phase 3 reste le contrôle final ([ARCH-009](../adrs/ARCH-009-etat-de-reprise-et-journal-des-effets.md)) |
| Preuves antérieures au bootstrap (`.git`, manifeste existants) : déduction faussée sans état | Moyenne | Faible | Lire `resume` et ses incohérences avant de poursuivre ([ARCH-009](../adrs/ARCH-009-etat-de-reprise-et-journal-des-effets.md)) |
| Journal des effets limité à ce que le skill déclare, non recoupé par l'audit | Moyenne | Faible | Accepté ; `effect` avant toute action globale ([ARCH-009](../adrs/ARCH-009-etat-de-reprise-et-journal-des-effets.md)) |
| Fichier mal rangé dans un module : non détecté par la génération (le chemin reste le même) | Moyenne | Faible | `scaffold.mjs --list-modules` et relecture en PR ([ARCH-010](../adrs/ARCH-010-modules-auto-decrits.md)) |
| Modèle localisé oublié : retombe sur le français sans erreur | Moyenne | Moyen | Combinaisons `full` et `full-en` de la matrice et test de parité ([ARCH-010](../adrs/ARCH-010-modules-auto-decrits.md)) |
| Dette : permissions de `settings.json`, étapes de `state.mjs`, contrôles de `audit.mjs`, migrations et blocs `@@module` transverses restent codés hors du dossier d'un module ; réponses aux `questions` non consommées par un schéma de configuration | Haute | Moyen | Acceptée ; un module ne peut pas encore tout porter seul ([ARCH-010](../adrs/ARCH-010-modules-auto-decrits.md)) |
| Teammate nommé autrement que son profil : non borné | Moyenne | Moyen | Convention de nommage ; consigné dans `pitfalls.md` ([ARCH-011](../adrs/ARCH-011-profils-d-agents-bornes-par-un-hook-unique.md)) |
| Profil intégré `Explore` : reçoit tout l'outillage en équipe, non borné | Moyenne | Moyen | Hors périmètre du hook ; consigné dans `pitfalls.md` ([ARCH-011](../adrs/ARCH-011-profils-d-agents-bornes-par-un-hook-unique.md)) |
| Ancien agent (`arc42-keeper`, `spec-reviewer`, `architecture-explorer`, `traceability-checker`) modifié par le projet : il reste en place avec son hook de frontmatter, hors de la table du hook, donc non borné par elle | Faible | Moyen | La migration 0003 ne supprime pas un fichier modifié et le signale par une note ; le retirer à la main s'il ne sert plus ([ARCH-016](../adrs/ARCH-016-les-profils-absorbent-les-agents-historiques.md)) |
| Perte assumée : plus d'exploration en équipe, un explorateur par option ; un seul `architect` compare les options | Haute | Faible | Accepté ([ARCH-016](../adrs/ARCH-016-les-profils-absorbent-les-agents-historiques.md)) |
| Perte assumée : la revue de spec n'a plus de contexte séparé, `qa-engineer` la fait dans le sien | Haute | Faible | Accepté ; relecture humaine ([ARCH-016](../adrs/ARCH-016-les-profils-absorbent-les-agents-historiques.md)) |
| Prompts de `architect` et de `qa-engineer` plus longs, donc moins lisibles | Moyenne | Faible | Relecture en PR ; garder la méthode des anciens agents avec la même exigence de preuves ([ARCH-016](../adrs/ARCH-016-les-profils-absorbent-les-agents-historiques.md)) |
| Hook non constaté sur l'outil `Agent` d'un teammate (constaté pour les autres outils, dont `Skill`) ; les teammates sans outil `Agent` n'ont pas été essayés sur `Agent` | Faible | Moyen | À vérifier en session d'équipe ; le hook couvre aussi l'ancien nom d'outil `Task` ; convention de nommage, consigné dans `pitfalls.md` ([ARCH-012](../adrs/ARCH-012-agents-skills-et-commandes-lancables-par-un-profil.md), [ARCH-011](../adrs/ARCH-011-profils-d-agents-bornes-par-un-hook-unique.md)) |
| Écrire puis exécuter : un profil écrit un fichier exécutable dans son périmètre (`tests/x.test.mjs`, règle `*.rules.ts`) puis le fait lancer par `run-checks.mjs` ou `archgate check` | Moyenne | Moyen | Le bornage est un garde-fou, pas un bac à sable ; relecture humaine des changements ([ARCH-011](../adrs/ARCH-011-profils-d-agents-bornes-par-un-hook-unique.md)) |
| Teammate isolé dans un worktree : écritures légitimes refusées (chemin calculé depuis `CLAUDE_PROJECT_DIR`) | Moyenne | Faible | Refus à tort, sans risque ; consigné dans `pitfalls.md` ([ARCH-011](../adrs/ARCH-011-profils-d-agents-bornes-par-un-hook-unique.md)) |
| Casse (`Tests/` refusé) pour les préfixes d'autorisation | Faible | Faible | Refus à tort sans risque ([ARCH-011](../adrs/ARCH-011-profils-d-agents-bornes-par-un-hook-unique.md)) ; les liens, jonctions et noms 8.3 sont résolus par le chemin réel ([ARCH-014](../adrs/ARCH-014-profils-optionnels-choisis-par-la-cle-profiles.md)) |
| Liste d'exclusion de `developer` plus faible qu'une liste d'autorisation : un dossier de gouvernance ajouté par un module n'est pas protégé tant qu'il n'est pas listé | Moyenne | Moyen | Tenir la liste à jour dans la table ; relecture par `qa-engineer` et par l'humain ([ARCH-014](../adrs/ARCH-014-profils-optionnels-choisis-par-la-cle-profiles.md)) |
| Shell de `developer` non borné : il peut écrire dans les dossiers de gouvernance | Moyenne | Moyen | Le prompt interdit de publier et, pour un changement existant, de modifier autre chose que `tasks.md` (il n'écrit les autres artefacts que sans `business-analyst`, dans `openspec/changes/<id>/`) ; relecture humaine ([ARCH-014](../adrs/ARCH-014-profils-optionnels-choisis-par-la-cle-profiles.md)) |
| Entrées de table `product-owner`, `business-analyst`, `acceptance-tester`, `scout`, `second-opinion`, `devops-engineer`, `compliance-reviewer` présentes sans la clé `profiles` : un agent du projet de même nom est borné sans l'avoir demandé | Faible | Faible | Nommer autrement l'agent du projet ; consigné dans `pitfalls.md` ([ARCH-014](../adrs/ARCH-014-profils-optionnels-choisis-par-la-cle-profiles.md)) |
| `regulatedDomain` : texte libre écrit dans le corps de `compliance-reviewer`, donc dans le dépôt ; une valeur détournée pourrait servir d'instruction | Faible | Faible | Liste blanche de caractères, aucune injection dans le frontmatter, valeur visible et relue en revue ([ARCH-014](../adrs/ARCH-014-profils-optionnels-choisis-par-la-cle-profiles.md)) |
| `keep` sur `profile-guard.mjs` : les profils choisis ne sont bornés que par la version du projet | Faible | Moyen | Le rapport l'avertit ([ARCH-014](../adrs/ARCH-014-profils-optionnels-choisis-par-la-cle-profiles.md)) |
| Teammate `developer` isolé dans un worktree : écrit sous `.claude/worktrees/` et se voit tout refuser ; `developer` étant par défaut, cela touche tout le code | Moyenne | Moyen | Refus à tort, sans risque ; même cause que le worktree ci-dessus ([ARCH-014](../adrs/ARCH-014-profils-optionnels-choisis-par-la-cle-profiles.md)) |
| Coût du hook : un `node` par écriture ou commande shell de la session, un second pour une commande de profil hors motifs | Haute | Faible | Accepté, quelques dizaines de millisecondes ([ARCH-011](../adrs/ARCH-011-profils-d-agents-bornes-par-un-hook-unique.md)) |
| Retrait du module `agent-profiles` : le hook déclaré dans `settings.json` et les fichiers générés restent ; sans la table, le hook ne borne plus rien | Faible | Faible | Supprimer à la main ([ARCH-011](../adrs/ARCH-011-profils-d-agents-bornes-par-un-hook-unique.md)) |
| Changement futur du contenu de `agent_type` : la correspondance profil-table casse | Faible | Haut | Tests de contrat du module ([ARCH-011](../adrs/ARCH-011-profils-d-agents-bornes-par-un-hook-unique.md)) |
| Réglage `agent` (`mainAgent`) appliqué à toutes les sessions du clone ; `project-lead` est borné par le hook et `disallowedTools`, mais sans garde mécanique contre l'auto-relecture (consigne seulement) | Moyenne | Moyen | Réglage facultatif et réversible (le retirer redonne l'agent par défaut) ; relecture confiée à `qa-engineer` par consigne ([ARCH-013](../adrs/ARCH-013-chef-de-projet-comme-agent-principal-active-par-mainagent.md)) |
| `project-lead` : les outils MCP d'écriture (GitHub) et les skills `context: fork` (qui lancent un agent hors de l'outil `Agent`) échappent au hook ; `Bash` est borné (lecture seule et commandes de pilotage) | Moyenne | Moyen | La règle « ne produit ni code ni spec » est répétée dans le corps du profil ; relecture humaine ; consigné dans `pitfalls.md` ([ARCH-013](../adrs/ARCH-013-chef-de-projet-comme-agent-principal-active-par-mainagent.md), [ARCH-012](../adrs/ARCH-012-agents-skills-et-commandes-lancables-par-un-profil.md)) |
| `project-lead` : la liste fermée de commandes de pilotage peut refuser une commande utile | Moyenne | Faible | Déléguer à `developer` ou demander à l'utilisateur ; le message de refus est explicite ([ARCH-013](../adrs/ARCH-013-chef-de-projet-comme-agent-principal-active-par-mainagent.md)) |
| `project-lead` : `--body-file` lit un fichier du dépôt, relatif | Faible | Faible | Chemin relatif sans `..` exigé par le hook ([ARCH-012](../adrs/ARCH-012-agents-skills-et-commandes-lancables-par-un-profil.md)) |
| Skill de méthode = consigne : le profil peut ne pas la lancer ; une skill permise mais non générée (module absent) est sans effet | Moyenne | Faible | Le corps du profil dit quand la lancer, un test vérifie qu'il la cite ; relecture en PR ([ARCH-016](../adrs/ARCH-016-les-profils-absorbent-les-agents-historiques.md)) |
| Outil `Skill` d'un teammate (`architect`, `qa-engineer`) : borné par nom de profil, constaté dans #114 ; reste la dépendance à la convention de nommage | Faible | Moyen | Convention de nommage ([ARCH-012](../adrs/ARCH-012-agents-skills-et-commandes-lancables-par-un-profil.md)) |
| Module `advisor` : fonction expérimentale, consigne d'appel, portée par les profils `sonnet`/`haiku`, qui n'est qu'une incitation (aucun mécanisme ne garantit ni ne plafonne l'appel), documentation susceptible de changer, usage par un teammate non établi | Moyenne | Faible | Aucun réglage écrit par le plugin ; constats datés dans `pitfalls.md` ; à vérifier en session d'équipe |
| Compte sans accès à `opus` : les agents déclarés `opus` retombent sur l'ordre de modèles de Claude Code | Moyenne | Faible | Éditer le frontmatter ; consigné dans `pitfalls.md` ([ARCH-015](../adrs/ARCH-015-le-plugin-n-ecrit-pas-de-reglage-payant-ou-experimental.md)) |
| `effort: high` sur Opus coûte plus ; `maxTurns` trop bas tronque un travail long | Moyenne | Faible | Valeurs fixes documentées, surchargeables par l'environnement ou le frontmatter ([ARCH-015](../adrs/ARCH-015-le-plugin-n-ecrit-pas-de-reglage-payant-ou-experimental.md)) |
| Surcharge `CLAUDE_CODE_SUBAGENT_MODEL` : consigne de l'advisor sur un profil passé en opus, niveau `effort` possiblement absent du modèle de remplacement | Faible | Faible | Non vérifié ; consigné dans la conception du changement 37 |
